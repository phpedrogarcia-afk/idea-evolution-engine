## 1. Context and Provenance of the Change

1. **Pre-existing Frozen Source of Truth:**
   - In M05.5R1, the output cap was calibrated and frozen at **`2048` tokens** (`M05.5R1-CONFIRMATORY-FREEZE-RECORD.json`, `m05_5r1_token_envelope.py`, `execute_m05_5r1_confirmatory.py`).
   - In the reference prospective experiment M05.4 (Attempt-004), no explicit `max_tokens` / `max_completion_tokens` parameter was passed to Groq (`client.chat.completions.create`), relying on provider server defaults. The maximum observed output size in M05.4 was 3,882 bytes UTF-8 (~811 tokens).
2. **Observed Binding Failure in Pilot-001:**
   - In `CEREBRAS-FREE-SACRIFICIAL-PILOT-001`, executed on Cerebras Cloud with model `gpt-oss-120b`, Condition B reached Stage 4 (`SYNTHESIZE`).
   - The model generated text until reaching exactly **2,048 completion tokens**, at which point the provider terminated the stream, truncating the JSON payload (`ValidationError: EOF while parsing a string`).
   - 5 of 5 provider requests returned HTTP 200 OK, proving the provider transport and strict JSON mode are functional, but the 2,048-token cap was observably binding.
3. **Causal Justification:**
   - This amendment is **NOT** justified by convenience, provider maximum support (Cerebras supports up to 40,960 completion tokens), or preference for longer answers.
   - It is justified **EXCLUSIVELY** because the frozen 2,048 limit produced a concrete binding truncation before confirmatory holdout execution.

## 2. Specification of the Amendment

1. **Previous Frozen Cap:**
   `OLD_OUTPUT_CAP_TOKENS = 2048`
2. **Amended Prospective Cap:**
   `NEW_OUTPUT_CAP_TOKENS = 4096`
3. **Symmetry Across Treatments:**
   The 4,096 cap applies identically and symmetrically to:
   - **Condition A (Baseline):** 4,096 max completion tokens
   - **Condition B (Simple Loop):** 4,096 max completion tokens (all stages)
   - **Condition C (Lean Loop L1):** 4,096 max completion tokens
   `OUTPUT_CAP_SYMMETRY = A_4096_B_4096_C_4096`. No treatment receives differential output freedom.
4. **Effective Scope and Immutability:**
   - **Effective Scope:** All M05.5R2 A/B/C provider requests.
   - **Effective From:** `CEREBRAS-FREE-SACRIFICIAL-PILOT-002` onward.
   - **Retroactivity:** `NO`.
   - **Pilot-001 Status:** Remains immutable (`INVALID_COMPLETE_SACRIFICIAL_EXECUTION_DUE_TO_BINDING_FROZEN_2048_OUTPUT_CAP`).
   - **Holdouts H01–H08 Accessed Before Amendment:** `NO`.
   - **Formal Unblind Before Amendment:** `NO`.
   - **Human Scoring Before Amendment:** `NO`.
