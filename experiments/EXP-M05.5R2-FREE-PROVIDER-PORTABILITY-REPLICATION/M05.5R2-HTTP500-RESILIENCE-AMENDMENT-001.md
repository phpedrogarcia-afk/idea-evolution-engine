## 1. Context and Concrete Empirical Motivation

1. **Evidência Observada no Attempt-001:**
   - 89 requisições consecutivas retornaram **HTTP 200 OK**.
   - 1 requisição (`H06-CONDITION_B:CONDITION_B:2`, estágio `ATTACK`) falhou com **HTTP Error 500: Internal Server Error** na infraestrutura da Cerebras Cloud.
   - Erros HTTP 429: **0**. Erros de schema estrito: **0**. Truncamentos de output cap: **0**.
   - O erro observado foi estritamente uma falha de transporte/infraestrutura transitória upstream.
2. **Definição da Classe de Falha:**
   - A falha é classificada estritamente como `TRANSIENT_PROVIDER_HTTP500`.
   - A documentação da Cerebras trata erros $\ge 500$ como erros transitórios de infraestrutura passíveis de replay idêntico.
   - O contrato `SDK_MAX_RETRIES = 0` permanece estritamente preservado. A resiliência é governada e observável deterministicamente no harness de replicação.

## 2. Frozen Resilience Contract

| PARÂMETRO | VALOR CONGELADO | NOTAS DE GOVERNANÇA |
|---|---|---|
| **Max Replays Idênticos por Chamada Lógica** | `1` | Máximo de 1 replay idêntico se HTTP status for exatamente 500 |
| **Max Replays HTTP 500 por Tentativa Completa** | `1` | Orçamento global de 1 replay para toda a tentativa de 24 células |
| **SDK / Transport Library Retries** | `0` | Proibido retries ocultos ou não instrumentados |
| **Gatilho Exclusivo** | `HTTP_STATUS == 500` | Requisição enviada e retorno HTTP 500 sem resposta semântica |
| **Erros Não Elegíveis (Fail-Closed)** | `400, 401, 403, 408, 410, 422, 429, 501, 502, 503, 504` | Qualquer outro erro encerra imediatamente o experimento |
| **Exigência de Replay Idêntico** | $\text{Payload}_{\text{replay}} \equiv \text{Payload}_{\text{orig}}$ | `ORIGINAL_SANITIZED_PAYLOAD_HASH == REPLAY_SANITIZED_PAYLOAD_HASH` |
| **Tempo Mínimo de Espera pré-Replay** | $\ge 15.0$ segundos | Re-entrada obrigatória no token-aware pacer antes do despacho |

## 3. Contabilidade Epistêmica e Registro

- Se requisição 1 $\to$ HTTP 500 e requisição 2 (replay idêntico) $\to$ HTTP 200:
  - $\text{LOGICAL\_CALLS} = 1$
  - $\text{PROVIDER\_REQUESTS} = 2$
  - $\text{HTTP500\_REPLAYS} = 1$
- A requisição física com falha permanece registrada de forma indelével no ledger encadeado por SHA-256 (`usage-ledger.jsonl`). Não há substituição ou ocultação de eventos.
- A regra **NÃO é reamostragem de qualidade** nem reparo de JSON: apenas é acionada quando nenhuma resposta semântica foi gerada pelo modelo.
- Se o replay autorizado retornar HTTP 500 novamente ou qualquer outro erro, a execução é **imediatamente interrompida** (fail-closed).
- Se uma segunda falha HTTP 500 ocorrer em qualquer momento posterior da tentativa (esgotando o orçamento de 1 replay por tentativa), a execução é **imediatamente interrompida**.
